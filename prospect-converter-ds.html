Foundations

The Foundations module defines the core visual and structural principles of the design system, ensuring consistency and scalability across all product modules.

It consists of: Colors, Icons, Typography, Grid & Layouts, Content Standards.

Challenge 1: Component status tracking

The problem

As the team grew to up to 5 designers working across the same design system, there was no way to tell whether a component was safe to reuse or had changed since the last time someone touched it. So designers kept pinging each other to confirm before using anything in a new screen.

The fix

In a team retrospective, we introduced a status label on every component: ready, in review, or deprecated, visible directly in the library.

The result

Designers could check a component's status at a glance instead of asking the team. This cut down the back-and-forth that used to happen before starting new screens.

Components

Components are reusable interface elements with variations and states. Unique components include extra rules. Basic structure was, component - variants - states - additional rules + links.

Challenge 2: Form guideline for the dev team

The problem

The product had many forms across B2B and B2C sharing a lot of common rules, but no documented reference for how they should be structured. Developers had no consistent way to know which components to use or how to place them, and every new form risked drifting from existing patterns.

The fix

In a weekly sync with the Dev team, we agreed to build a Form Guideline covering all necessary variations: single controls, control or text groups, and subgroups.

The result

Developers could assemble new forms directly from the documented rules, without needing a designer to spec every screen individually.

Patterns

Patterns show how existing components work together as part of a bigger interface. For example, the “Changes Saving” pattern explains what happens when a user edits something and saves it. It shows when to use it, like in forms or settings.

Interaction like this is listed step by step with screen examples, showing how the components behave. Instead of repeating rules, each step links to the components already described elsewhere.

Challenge 3: Dates and titles formatting

The problem

There was no defined standard for date and title formatting. I spotted inconsistencies across different screens, each apparently decided independently by whoever built that screen.

The fix

I requested a team sync to define a formatting rules group, documented after discussion and linked to the relevant component pages as a reference.

The result

New screens followed one consistent format by default, instead of each designer choosing their own.
