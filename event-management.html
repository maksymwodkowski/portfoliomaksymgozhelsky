Event Requests List

Comes as a “Intake & Sourcing” module. Main page for the events managers. Here they are able to set priority, change status, view existing details and assign it to a particular owner.

Key challenge: Event page design

The initial request

Event coordinators needed to manage a request that could contain multiple related events (a client asking for 3 separate roundtables, for example), each moving through its own pipeline stage – Intake Call, Request for Proposal, Sourcing Options, Contract – while also filling in two distinct sets of information for each: logistics details and a day-by-day agenda.

What we found

Splitting this across separate screens meant coordinators lost context constantly – switching between the client's original request, the event's current stage, and the operational details they were filling in. With multiple sub-events per request, keeping track of which event was in which stage, on which screen, became its own source of errors.

The fix

We combined everything into a single view: a event-switcher at the top for handling multiple sub-events under one request, a stage tracker beneath it, and a two-column layout for event details and agenda side by side – so both could be filled without switching context. A collapsible reference panel on the right kept the original request, notes, and history log visible on demand, without forcing a separate screen just to check what the client had asked for.

The result

Coordinators could manage a multi-event request end to end from one screen – tracking pipeline stage, filling logistics and agenda, and referencing the original ask, all without navigating away.
